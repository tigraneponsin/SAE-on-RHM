# SAE on RHM — Current Status and Concerns (20/04/2026)

## Current Workflow

We have a transformer trained on the fixed-tree RHM (classification task). After layer $k$ of the transformer, we train an SAE on all token positions' residual stream activations. The goal is to check whether SAE features can be associated with specific **latent variable values** at specific **positions** in the RHM parse tree.

### Metric

For a token at position $p$ in the input sequence, we look at the SAE trained on position $p$ after layer $k$ of the transformer. We then evaluate correspondence with the latent variable at level $L - k - 1$, position $\lfloor p / 2^{k+1} \rfloor$ in the hierarchy.

The score for each latent value $a_j \in \{a_1, \ldots, a_v\}$ and each SAE feature $f_i \in \{f_1, \ldots, f_N\}$ (currently conditioned on token position) is:

$$S(f_i, a_j) = \mathbb{E}[f_i \mid \text{latent} = a_j] - \mathbb{E}[f_i]$$

For each latent value $a_j$, we sort features by this score $S(f_i, a_j)$.

### Current Plots

1. **Top-K features plot:** For each latent value $a_j$, show the top $K$ features with the best $S_{ij}$.
2. **Specificity plot:** For the best feature for a given $a_j$ (i.e., the feature $f_{i^*}$ maximizing $S_{i^*j}$), plot $S_{i^*,l}$ for all other latent values $l \in \{1, \ldots, v\}$. This checks whether the best feature for $a_j$ also responds to other latent values (add cosine similarity check between encoder directions as an alternative/complement).

## Current Issue: Multiple Features for a Single Latent Value

### Observations

There is a critical L1 coefficient $\lambda_c$ that separates two regimes ("active tokens" = tokens that participate in the classification, as opposed to dead/padding tokens):
- I define $\lambda_c$ as the value after which the transformer's performance is worsened by the insertion of the SAE

- In the regime $\lambda_1 < \lambda_c$, the number of ever-active features is higher than expected if we look at the latent structure and the minimum information need to recover the class (overcomplete dictionnary). As we approach $\lambda_c$, the mean-active feature per SAE pass through approaches 1.

- **When $\lambda_1 < \lambda_c$ (on active tokens):** We sometimes observe **multiple features for a single latent value**, BUT each feature maps to a **unique latent value** (one-to-many from latent to features, but one-to-one from feature to latent). Features are monosemantic but redundant.

- **When $\lambda_1 > \lambda_c$:** We observe **multiple latent values for a single feature**. Features become polysemantic — a single feature fires for different nonterminals.

- **For "dead tokens" (padding/inactive positions):** Even at $\lambda < \lambda_c$, we see **multiple latent values for a single feature**. Features on these positions are polysemantic regardless of sparsity.

- Dead tokens after layer 0 seem to resurrect after layer 1 !

-For non dead tokens at layer k that originate from the same ancestor at level L-1-k, the SAEs tend to often use the same features for the same latent value (which is kind of what we hoped). However, it is not systemic, and specifically after layer k=L-1, they all should encode the root, but the SAEs seems to divide the tree into the two first brancehs in terms of feature utilization.

## Open Questions

### 1. Is this actual feature splitting?
Even though the mean number of active features per input is $\sim 1$, we see multiple features per latent value. Is this genuine feature splitting (in the Anthropic sense), or a training artifact?

### 2. Could it be synonym specification?
The multiple features for a single nonterminal might be splitting along **synonymic groups** — i.e., each feature detects not just "nonterminal $a$" but "nonterminal $a$ generated by a specific synonym tuple." This would be meaningful splitting (the SAE is discovering finer structure than the nonterminal level). **Check:** condition the analysis on which synonym produced the input and see if the split features separate cleanly by synonym.

### 3. Can we regroup them?
If multiple features correspond to the same latent value, can we merge/cluster them (e.g., by cosine similarity of their encoder or decoder vectors) to recover one-to-one correspondence?

### 4. Can we do stats after regrouping?
After merging features that correspond to the same latent, do the regrouped features have cleaner metrics ($\eta^2$, specificity, coverage)?

### 5. Can we reconstruct the whole tree after regrouping?
After regrouping features, can we reconstruct the full parse tree (all nonterminals at all levels) from the SAE decomposition? This is the ultimate test of whether the SAE captures the hierarchical structure.

### 6. Causality?
Can we do causal interventions (ablation/steering) using the SAE features and verify that the effects match the ground-truth predictions from the RHM structure?

## Ideas to Investigate

- **Check encoder cosine similarity** between features that map to the same latent value. If they have similar encoder directions, it's degenerate splitting. If they point in different directions, they might be capturing different aspects (e.g., different synonyms, different positional contexts).

- **Condition on synonyms** to distinguish meaningful splitting from degenerate splitting.

- **Compare across layers** — does the splitting pattern differ between early and late transformer layers?
